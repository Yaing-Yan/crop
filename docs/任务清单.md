## 1. 任务分解与状态

### A. 语言能力（rGCC 扩展）—— 硬骨头，必须先把"调用 ROM 例程"打通

- [ ] **A1. ROM 例程调用机制（路线 B）+ 库函数 ABI 表**：这是 A2~A5 的前置。
  - **设计要点（用户明确）**：C 层面一切以**变量/函数参数**呈现；
    "把参数搬进寄存器"是 **ROP 层/编译器**的活儿，不是用户的责任。
    即：`void rprint(unsigned char font, unsigned char row, unsigned char *text);`
    → rGCC 依据该库函数的 **ABI 表** 生成"从变量装载到寄存器"的槽序列
    （font→`R0`、row→`R1`、text→`ER2`），再进入 ROM 例程。
  - 要建的数据结构（`crop/libabi.py`，或 `include/` 里的声明式表）：
    ```
    { name: "rprint", entry: <标签>, skip_push_lr: true/false,
      regs: ["R0", "R1", "ER2"], args: ["u8", "u8", "u8*"] }
    ```
    地址一律来自标签表（C1），不写死。
  - 已知事实：RopIDE 的库函数（`memcpy`/`strcpy`/`print-*`/`screen-on`/`rt-fix`）都是
    **进入 ROM 函数体（跳过开头 `PUSH LR`，即 +2 进入）**，函数末尾 `RT` 从**硬件返回栈**返回，
    因此必须配 `rt-fix` 把返回地址准备好。
  - 待做：用真机/模拟台实测 `rt-fix`（verF `0x2BAD4`）的链契约：
    它吃几个链上字节、把什么放进硬件返回栈、之后 `RT` 会返回到哪里。
    参考 `docs/step-2-报告.md` 与 `crop/vocab.py`。
  - 交付：`crop/libcall.py`（或 `interp.py` 的 L4 层）：把"调用 ROM 函数 F、参数在寄存器里、
    返回后继续链"翻译成固定槽序列；并写进解释器。
- [ ] **A2. 函数**：`int f(int a){...}` 定义 + 调用 + `return`。
  - 语义：CROP 里"函数"= 链内子程序（用 `POP ER14`/枢轴做调用与返回）或用 ROM 例程（A1）。
  - 最省路径：**先把用户写的 C 函数内联展开**（单层调用），同时支持调用 ROM 库函数（A1）。
- [ ] **A3. 数组**：`unsigned char a[8];`，下标为常量表达式时 → 编译期算出地址；
  下标为变量时 → 需要指针/索引寻址（依赖 A4 的字节传送与加法）。
- [ ] **A4. 指针与算术**：`p[i]`、`*p`、`p+1`。当前只有常量地址 `*(u8*)ADDR = v` 可用；
  运行时指针需要：字节传送合成（`→R2`/`→R7`）+ 加法 gadget（见 `docs/step-2-报告.md` 路线 A）。
- [ ] **A5. 结构体**：`struct { … } s;`、`s.field`、`s->field`、数组套结构体。
  依赖 A3/A4 的地址计算；字段按常量偏移可直接落到 `--data-base + offset`。
- [ ] **A6. 预处理 `#include`**：rGCC 目前直接拒绝 `#`。需要一个极简预处理层：
  `#include "x.h"`（按 `-I` 目录查找）、`#define NAME value`（纯文本常量替换）。
  头文件里只放 **声明 + `#define` 常量 + 内联/C 包装函数**，不引入 libc。

### B. 头文件（用户点名先做）

- [ ] **B1. `include/rstdio.h`**
  - ⚠️ **用户明确要求（必须遵守）**：显示文本的 API **不能依赖寄存器传参**，
    必须用**变量**（C 变量/内存）作为参数与状态。也就是说：
    调用方写 `rprint(font, row, text)`，由**封装函数内部**把值搬进 ROM 例程要求的
    `r0`(字体大小) / `r1`(高度) / `er2`(文本地址)。
    → 因此需要**从内存装载到指定寄存器**的原语（`L Rn, off[BP]` 已有若干；
      把 16 位地址装进 ER2 需要"字节传送合成"，见 A4）。
    这条要求也意味着 `rprint` 这类函数必须先有 A1（ROM 例程调用机制）与 A4（字节传送），
    否则只能做"编译期把值直接编进链"的退化版本（仅支持常数字体/行号 + 常量字符串地址）。
    退化版本可以先做：`rprint_const(font, row, "text")` —— 三个参数都是编译期常量，
    rGCC 直接把 `POP ER14 + 地址` / `POP R0 + 字体` / `POP R1 + 行号` 编进链，不碰寄存器间传送。
  - `rputs(const char *s)` / `rprint(u8 font, u8 row, const char *s)` →
    封装 **`0x221BE`**（verF）：`r0=字体大小`（`0x0E` 正常 / `0x0A` 小字体 / `0x08` 表格小字体）、
    `r1=高度(行)`、`er2=文本地址`。
    ⚠️ 注意与 RopIDE 已收录的同族 gadget 对齐：`print-0ynf`=0x221AE、`print-0f1y`=0x221B2、
    `print-1ysf`=0x222A8、`print-0x1y`=0x0821E。用户给的 **0x221BE** 需要**先用反汇编与真机核对**
    到底是"进入函数体（跳过 PUSH LR）"还是"函数入口"，再决定 +2 与否。
  - `rrefresh(void)` → 封装 **`0x08772`**（DDD4 → 显存刷新）
  - `rclear(void)` → 封装 **`0x07F6C`**（清空 DDD4）
  - `#define SCREEN_BUF 0xDDD4`（用户给的地址；写入屏幕缓冲区）
- [ ] **B2. `include/rstring.h`**：`rstrcpy`(0x203C8)、`rstrcat`、`rmemcpy`(0x0875C)、`rstrlen`
- [ ] **B3. `include/rstdlib.h`**：`rsleep`(0x091D8)、`rscreen_on`(0x0937C)、关机/延时等

### C. 无硬编码原则（用户反复强调）

- ROM 地址**不得写死在 C 代码或编译器里**。可行方案（择一或组合）：
  1. `include/*.h` 里用 `#define` + 一个**由扫描/配置生成**的地址表
     （例如 `tools/crop-labels` 从 RopIDE 的 `gadgets.json` 或 `_disas.txt` 生成 `include/romlabels.h`）；
  2. 或把这些地址放进 `launcher.conf` 风格的配置文件，由 rGCC 在 `--rom-labels FILE` 时读入；
  3. 保留"从 ROM 扫描推导"的通路（如 `find_pivots`/`find_pop_gadgets` 的做法），
     对可推导的原语（pop/块写/枢轴）继续推导，对语义型例程（print/memcpy）用标签表。

## 2. 已验证的关键知识（不要重新踩坑）

* **注入规程**（详见 `docs/注入规程.md`）：链 → `0xEC00`；launcher → `0xD248`
  （`FD 24 <左地址-10h 小端> <该 Ver 枢轴编码>`，VerC `7B 23 42` / VerF `8F 23 42`）；
  长度账本 `0xD244..0xD247 = 07`；清 `0xD180`；按【→】再按【=】。
* **机器栈在 `0xE9xx~0xEBxx`**，链不要放那里。
* **块写 gadget 必须从 `LEA [ERn]` 指令进**（`0x17DE8`），不能从外层起点（`0x17DE2`）。
* **MCP 按键必须长按 ≥0.9s**；机器卡死时先复位（判据：`PC=0x91AA && SP=0xEE34`）。
* **两个 Ver 的枢轴**：VerC `0x2237A`、VerF `0x2238E`（同形态
  `MOV SP,ER14 ; POP QR8 ; POP QR0 ; POP PC`），且都能由扫描推出。
