    必须用**变量**（C 变量/内存）作为参数与状态。也就是说：
    调用方写 `rprint(font, row, text)`，由**封装函数内部**把值搬进 ROM 例程要求的
    `r0`(字体大小) / `r1`(高度) / `er2`(文本地址)。
    → 因此需要**从内存装载到指定寄存器**的原语（`L Rn, off[BP]` 已有若干；

    这条要求也意味着 `rprint` 这类函数必须先有 A1（ROM 例程调用机制）与 A4（字节传送），
    否则只能做"编译期把值直接编进链"的退化版本（仅支持常数字体/行号 + 常量字符串地址）。
    退化版本可以先做：`rprint_const(font, row, "text")` —— 三个参数都是编译期常量，
    rGCC 直接把 `POP ER14 + 地址` / `POP R0 + 字体` / `POP R1 + 行号` 编进链，不碰寄存器间传送。
  - `rputs(const char *s)` / `rprint(u8 font, u8 row, const char *s)` →

### C. 无硬编码原则（用户反复强调）

- ROM 地址**不得写死在 C 代码或编译器里**。可行方案（择一或组合）：
  1. `include/*.h` 里用 `#define` + 一个**由扫描/配置生成**的地址表
     （例如 `tools/crop-labels` 从 RopIDE 的 `gadgets.json` 或 `_disas.txt` 生成 `include/romlabels.h`）；
  2. 或把这些地址放进 `launcher.conf` 风格的配置文件，由 rGCC 在 `--rom-labels FILE` 时读入；
  3. 保留"从 ROM 扫描推导"的通路（如 `find_pivots`/`find_pop_gadgets` 的做法），
     对可推导的原语（pop/块写/枢轴）继续推导，对语义型例程（print/memcpy）用标签表。

## 2. 已验证的关键知识（不要重新踩坑）

* **注入规程**（详见 `docs/注入规程.md`）：链 → `0xEC00`；launcher → `0xD248`
  （`FD 24 <左地址-10h 小端> <该 Ver 枢轴编码>`，VerC `7B 23 42` / VerF `8F 23 42`）；
  长度账本 `0xD244..0xD247 = 07`；清 `0xD180`；按【→】再按【=】。
* **机器栈在 `0xE9xx~0xEBxx`**，链不要放那里。
* **块写 gadget 必须从 `LEA [ERn]` 指令进**（`0x17DE8`），不能从外层起点（`0x17DE2`）。
* **MCP 按键必须长按 ≥0.9s**；机器卡死时先复位（判据：`PC=0x91AA && SP=0xEE34`）。
* **MCP 怎么起来**：`cd <EMU_DIR> && ./CasioEmuMsvc models/fx991cnxfVirtual`
  —— 机型目录必须当**位置参数**传，否则插件不加载、3001 不监听；
  本机 GUI 不接收合成输入（uinput 点击/XTest 都无效），别指望用鼠标点选机型。
* **ROM 的显示任务只在主线程跑**：链尾 `while(1)` 会让 LCD 停在最后一帧（内存里却已经是新内容）。
  想让 LCD 真的变，得自己接管显示任务（或让程序结束时把控制权还回去）。
* **两个 Ver 的枢轴**：VerC `0x2237A`、VerF `0x2238E`（同形态
  `MOV SP,ER14 ; POP QR8 ; POP QR0 ; POP PC`），且都能由扫描推出。
