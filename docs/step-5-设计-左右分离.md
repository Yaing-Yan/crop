# 第 5 步设计：左右分离（程序存储区 ↔ 运行区）

> 起因（真机实测）：链放在 `0xE9E0`（输入区/栈附近）时，`按右 → 按=` 触发后，
> **链的前 10 字节完好，第 10 字节起被改写成 `38 07 01 00`（gadget 地址 0x10738）**，
> 于是引导成功（`SP` 走到链内 `0xEA06`）但块写取到垃圾、`PC` 跑到 ROM 外（`0xACBF8`）。
> 用户判断：这是**计算器自身 PUSH 造成的污染**（中断/按键/那次搬运都会用栈），
> 而栈就在 `0xE9D0` 一带 —— 正是我们放链的地方。

## 方案：解释时可选"运行区与程序区分离"

**在 C 层面完全不体现**（用户明确要求）：rGCC 只产出机器码，链怎么摆、跑在哪一侧，
是**解释器/链布局**的事。所以这是一个解释器开关：

```
crop-rop --separate --left-base E9E0 --right-base D3C0 …
```

语义（与 RopIDE 的 `.rop` 完全一致）：

```
左侧 = 程序储存地址（leftStartAddress）  —— 程序被注入/摆放的地方
右侧 = 运行地址     （rightStartAddress） —— 链真正执行、SP 所在的地方
```

`--separate` 打开后，生成的链结构变成：

```
[前导码]  把整条链从左地址复制到右地址
[枢轴]    SP := 右侧首槽
[主体]    块的地址槽；所有链内绝对地址改用【右基准】
```

## 参考实现：Pixel Editor 的前导码就是干这个的

RopIDE 的 Pixel Editor Pro 在 `<-start>` 处有这么一段（左侧锚点，说明它在左侧执行）：

```
<-start>
 [$main-end - $main-s] [$main-s] [$main] [$main - C]   // 长度、左源、右目的、偏移差
 C4520100        // MOV ER0, ER8      （er0 = er8）
 8aCD0000        // …                  （跳转/复制相关）
```

即：**长度 + 左源 + 右目的**四个字，后面接 ROM 里现成的复制/搬运例程。
这也解释了为什么 `.rop` 文件必须同时记录左右两个地址 —— 同一份字节，两套地址视图。

## 实现清单（crop/interp.py + crop/chain.py）

1. `Options` 增 `separate: bool = False`（`right_base` 已有），CLI 加 `--separate`。
2. **前导码**（必须放在链的**最前面**，把"污染窗口"压到最小）：
   - `POP XR0` → `ER0 = 右目的`；`POP XR4` → `ER2 = 左源`；
   - 长度：**延迟常量**。`ChainBuilder` 已支持前向引用（`value_expr` 占位、`finalize()` 回填），
     收尾时 `define("ROPLEN", 链长)` 即可，不需要两遍生成。
   - 追加 ROM 里**推导**出来的 memcpy 型 gadget（见下）。
3. **枢轴**：复制完用现有的"取数 + `MOV SP,ERn` 干净枢轴"把 SP 指到右侧首槽，
   值 = `右地址 + 前导码长度`（右侧基准）。
4. **地址基准切换**：`pivot_side=right`，锚点用 `<name>`（右）而不是 `<-name>`（左）——
   DSL 里两套锚点、解释器里 `anchor_sides` 都已经实现，只是还没被 `--separate` 串起来。
5. C 侧零改动。rGCC 不需要知道链跑在哪一侧。

## 必须先解决的两件事（下一轮）

1. **memcpy 型 gadget 必须"推导"而不是写死**（`0x0875C` 是 VerF 的社区值）。
   做法：在词表/`by_addr` 里找"以 `BL`/`B` 进入、内部含 `L …[ER2]`/`ST …[ER0]` 循环、
   以 `RT`/`POP PC` 退出"的例程；或退一步先用**链内自复制**（逐字节 `L`/`ST`，代价高但完全可控）。
   同时要用真机/模拟器**实测它的链契约**（寄存器约定、吃几个链上字节）—— 这是路线 A 的"实测判据"。
2. **污染窗口**：前导码自身也活在会被 PUSH 踩到的区域，所以它必须极短
   （约 3~4 个槽 + 数据），且复制要一次成块（8/16 字节为单位），不能逐字节磨。

## 备选（成本更低，先试）

* `--left-base EB00`：把链放到搬运/栈够不到的更远处（`launcher` 的第二个字段可控，
  launcher 会自动变成 `FD 24 F0 EA 7B 23 42`）。这不需要 memcpy，**先验证它是否够用**；
  如果够用，`--separate` 就是"更彻底但更贵"的方案，可以后做。
* 找到"输入长度/光标"变量并设成 7，让那次搬运只搬 7 字节 —— 治本但需要先定位该变量。
