# 第 3 步报告：rGCC v0（受限 C 子集 → 可 100% 翻译的 `.bin`）

> 产物：`crop/rgcc.py`、`tools/rgcc`、`tests/test_rgcc.py`（自测共 25 项全绿）。
> 跑法：`tools/rgcc --rom-dir <VERF_MODEL_DIR> demo.c -o out/demo.bin --rop out/Rop.bin --dsl out/demo.rop`

## 一、为什么是"受限"子集：第 1、2 步给出的硬约束

| 事实 | 后果 |
|---|---|
| ROM 里"干净可内联"的 ALU 只有 **48 种**，寄存器/立即数组合固定 | 无法编译任意表达式 |
| 全片只有 **1 个**变量槽同时存在 `L` 与 `ST`（`R7 @ -10h[BP]`） | 无法做通用变量分配 |
| `mov_reg` 只有 10 种 | 无法自由搬寄存器 |
| 没有"条件跳过一个链槽"的 gadget | `if`/`while(cond)` 无法实现 |

所以 rGCC v0 的边界是**"能 100% 翻译"**，而不是"支持完整 C"。

## 二、语言与代码生成

支持（当前）：

```c
unsigned char flag;            // 变量自动分配 RAM 地址（或 --data-base 指定）
void main(void) {
    flag = 1;                  // 常量写内存
    while (1) { flag = 0; }    // 无条件循环（→ 栈枢轴回跳）
}
```

代码生成用两条**已被真机验证的 RopIDE 惯用法**：

* `x = 常量` → `POP XR0`（一次装 ER0=地址、R2=值）+ `ST R2,[ER0]`
  —— 正是 RopIDE 手工程序里的 `#pop-xr0; … #byte-set;`；
* `while(1)` → `B`（无条件跳转）→ 解释器用 `#pop-er14; [$label-2]; #<pivot>;` 实现。

**`.bin` 的内联数据约定**（本项目新增，第 2 步解释器已实现）：
`POP <reg>` 在 `.bin` 里紧跟它要弹走的 `sp_delta` 个字节，解释器把它们原样搬进 ROP 链。
这是"任意常量"的唯一来源。

**构造性保证**：编译完立刻用扫描器逐条核对"该指令的字节在 ROM 里存在且后面紧跟 `POP PC`"，
任何一条不满足就 `RgccError`（`verify_translatable`），因此解释器覆盖率恒为 100%。

## 三、实测：完整流水线

`demo.c`（2 个变量、4 次赋值、1 个死循环）：

```
变量：flag@D180, dot@D181
.bin（36 字节）：
  2E F0 80 D1 01 00 01 92   POP XR0[内联:F5 D0 01 00] ; ST R2,[ER0]     // flag = 1
  2E F0 81 D1 00 00 01 92                                                // dot  = 0
  2E F0 80 D1 00 00 01 92                                                // flag = 0
  2E F0 81 D1 FF 00 01 92                                                // dot  = 255
  00 F0 10 00               B 回跳到 0x10

→ Rop.bin（58 字节链）：0 条不支持、0 条警告
  #g093C0; F5D00100 #g203D2;  …  <-L0010> … #g10742; [$L0010 - 2] #g10740;
  （g093C0 = POP XR0 ; POP PC，g203D2 = ST R2,[ER0] ; POP PC，
    g10740 = MOV SP,ER14 ; POP ER14 ; POP PC）
```

`out/demo.rop` 可被 RopIDE 直接打开继续编辑。

## 四、第 4 步要做的（按优先级）

1. **条件分支**（解锁 `if` / `while(cond)` / 基本 C）。
   已找到线索：`testing.rop` 注释里的 `D68D3030` 是 ROM 地址 **0x08DD6** 上的
   "ER0 == ER2 → R0 = 1（否则 0）" gadget。配合 `0/1 索引 × 2 + 表基址` 与枢轴，
   就能做**跳转表式条件分支**（代价约 5~6 个槽/次，落在设计文档说的 128~1024 字节预算内）。
   实施前必须用模拟器把它的链契约（吃几字节、改哪些寄存器）实测确认。
2. **ROP 模拟台**：用 `<LIFTED_PY>` 把生成的链放进 RAM 跑一遍，
   对比"直接执行 `.bin`"的最终寄存器/内存状态 —— 这才是端到端的正确性证明。
3. **launcher（+2 法）**：目前只差 `FD 24 …` 那 2 字节的语义；有了模拟台就能实测确定，
   然后写 `launcher.conf`。
4. **路线 B 补充**：真实程序（绘图/字符串/数学）靠"在 C 层面匹配 ROM 例程 +
   `rt-fix`/`BL`"收益最大，作为条件分支之后的重点。
