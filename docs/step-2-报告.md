## 二、解释器三层结构（已完成的部分）

| 层 | 做法 | 代价 | 状态 |
|---|---|---|---|
| **L1 块复用** | 最长匹配 ROM 里逐字节相同、后面紧跟 `POP PC` 的序列 | 4 字节/块 | ✅ |
| **L2 等价转义** | `MOV Rn,#imm`/`MOV ERn,#imm` → `POP Rn/ERn` 原语 + 链上数据（任意常量） | 4+2~8 字节 | ✅（这一类） |
| **L3 跳转** | 程序内部 `B label` → `#pop-er14; [$label-2]; #<pivot>;`（栈枢轴） | 10 字节 | ✅ |
| L3 条件分支 `BC` | —— | —— | ❌ **本 ROM 无实现**（见第四节） |

实现要点：

* 解释器**同时**走两条路：直接构造字节 + 生成 RopIDE DSL 文本再回编译，
  两者必须完全一致，否则立刻报错（`test_dsl_and_bytes_agree`）。
* 每个 L1/L2 决策都记录命中的 ROM 地址；测试逐个断言"该地址逐字节相同 +
  后面紧跟 `8E F2`"（`test_l1_blocks_are_real_rom_gadgets`）。
* 翻不动的指令**明确报"不支持"并列出原因**，绝不猜（`test_unsupported_is_reported_not_guessed`）。

顺手修掉三个真 bug（都是测试/对拍抓出来的）：

1. `POPL` 多字段字（如 `0xFF8E = POP LR,PSW,PC,EA`）曾被误判成纯 `POP PC` → 现在只认 `0xF28E`；
2. ALU 立即数在反汇编文本里是**十进制**，我曾按十六进制解析（`MOV R0,#224` 变成 `#548`）；
3. 枢轴 gadget 若以 `RT` 结尾（`MOV SP,ER14; POP ER14; RT`）**不能续链**，必须先过滤；
   左式编码（`#-name;`）会把地址低字节 `00` 改成 `01`，必须避开这类地址。

## 三、ROP 词表（这个 ROM 到底能当什么指令集用）

`crop/vocab.py` 自动挖出 **1188 条"干净可内联（指令数 ≤3）"原语**，完整清单见
`out/step2-vocab.txt`。关键部分：

```
取数原语 POP <reg>（链上取任意值）：19 种 / 304 个
  XR4×77  ER8×52  QR8×49  ER4×33  XR8×28  XR0×9  ER14×8  XR12×8
  ER0×7   QR0×5   R8×5    ER2×4   R0×4    R4×4   ER12×3  ER10×2  ER6×2  R12×2  R9×2
  → 用 POP QR0 + POP QR8 就能把整个 R0~R15 寄存器组从链上装满
寄存器传送 mov_reg：只有 10 种（ER0←ER8、ER0←R2、ER2←ER12 …）
ALU：48 种，且**寄存器/立即数组合是固定的**
  CMP R0,#0 ×9 | ADDC R3,#122 ×4 | OR R0,R1 ×3 | SUB R2,R8 ×3 | MUL ER2,R10 ×2
  SRA R9,R8 ×2 | SLL R12,R4 | SLLC R11,#4 | SRL R1,#2 | DAA R7 | XOR R2,R6 …
干净栈枢轴：66 个（`MOV SP,ERn` + 只跟 POP，以 POP PC 结尾），最省的是
  @10740  `MOV SP, ER14 ; POP ER14 ; POP PC`（枢轴后只跳 2 字节）
```

**结论：这个 ROM 没有"通用指令集"。** ALU 只有 48 种固定形态，寄存器传送只有 10 种。
所以"任意 nX-U16 代码都能自动翻译"是不成立的。

## 四、覆盖率实测（用真实 ROM 函数体当代理）

`tools/crop-eval` 取 150 个真实函数体（`PUSH LR` … `POP PC`，共 24350 条指令）：

```
L1 块复用      2417 条 ( 9.9%)
L2 等价转义     612 条 ( 2.5%)
L3 跳转            0 处
不支持        21321 条 (87.6%)
链总长 13120 字节（0.54 字节/指令）
```

最常翻不动的指令：

```
×348 MOV R1, #0            （没有 POP R1 原语；只能用 POP ER0 连 R0 一起写）
×280 L ER0, -0040h[ER14]   （帧指针相对访存：栈结构，rGCC 本来就该禁止）
×204 MOV ER0, ER14         （寄存器传送词表太薄）
×202 PUSH LR               （栈操作，必须禁止）
×172 BL / B                （外部调用与跳转）
×141 MOV ER0, ER4          ×140 ST ER0, -0040h[ER14]   ×139 ADD ER0, #1
```

这组数字要正确解读，**它低估了 rGCC 生成代码的可用率**：ROM 里 87.6% 翻不动的
指令里，很大一部分是"栈/帧指针/外部调用"，而 rGCC 被要求**根本不许生成**它们。
真正要控制的变量是：**rGCC 只用词表内的形态**，那样 L1+L2 覆盖率是构造性的高。

## 五、第 2 步撞到的硬墙：条件分支

`BC cond, target` 需要"能按条件多跳过一个链槽"的 gadget。第 1 步已做过全 ROM 搜索：

* `BC cond,+1` 后面跟 `SP+=4` 再 `POP PC` 的模式：**0 个**；
* 放宽到"`BC cond,+1` 且 A+4 就是 `POP PC`"：只有 7 处，而且 A+2 是 `MOV R0,#0/1`
  （两条路径最终落到**同一个** `POP PC`），无法用来跳过链槽。

因此在本 ROM 上，条件分支**无法**用单个 gadget 实现。可选的实现路径有三条，
都还没有做：

1. **区域 gadget（含内部分支）**：把 gadget 定义从"直线序列"放宽到
   "执行从 A 进入、从若干 `POP PC` 退出的小区域"。需要一个能跟随 `BC`
   前向分支的有界区域扫描器；然后在区域里找"两条退出路径消耗链字节数不同"
   的那种，就是天然的条件跳转原语。
2. **跳转表 + 无分支索引**：把条件编译成 0/1 索引，查链上的跳转表再枢轴。
   需要能算 0/1 的无分支比较（如 `SUB` 产生借位 + `SLLC` 把 C 移进寄存器），
   而当前词表里 `SLLC` 只有一个 `SLLC R11,#4`，不够。
3. **借 ROM 例程当裁判**：用 `BL`/`rt-fix` 调 ROM 里的比较/返回 0-1 的函数。

## 六、下一步（第 3 步）的三条路线，需要你选一条

* **路线 A（最贴设计文档）"语义 gadget 合成"**
  把"等价"从"单条指令模板"升级为**规划器**：给定一条（或一小段）目标指令，
  在词表里搜索 gadget 组合，使净效果等价，用 `rom991cnx_lifted.py` 跑真 ROM
  **实测验证**（这也是第 4 步要搭的 ROP 模拟台）。最忠实于"逐条转义"的设想，
  但要写搜索器 + 效果模型，工作量最大。

* **路线 B"ROM 例程即库函数"**
  承认无法逐指令翻译，改成**在 C 层面匹配 ROM 例程**：`memcpy/strcpy/乘除/显示`
  等直接以 `rt-fix` 方式调用 ROM 现成函数。对真实程序收益最大（绘图、字符串、
  数学），但需要先把硬件返回栈机制搞通，属于第 4 步的 `launcher/rt-fix` 工作。

* **路线 C"受限 rGCC 先行"**
  先把 rGCC 做出来，只支持词表内的形态 + 直线代码 + 无条件跳转（无 `if/while`），
  快速打通"`.c → .bin → Rop.bin`"的完整流水线并出可运行样例；条件分支留待后续。
  最快能给你看到端到端成果。

我的建议：**C 先打通流水线（1 步内可见成果），同时把 A 的"无分支索引比较"当作
一个小目标顺带解决（`SUB`+`SLLC` 组合），这样第 4 步再用 B 补齐库函数。**
